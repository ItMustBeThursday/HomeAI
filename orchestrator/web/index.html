Queue work and walk away. Jobs run in the background with no approval step: the agent keeps going when it runs out of turns, retries failures, and resumes after a restart. It only stops for something it cannot safely do alone (deleting with no backup, sending anything out, purchases, publishing). Those show as needs-input with the question.

Timed jobs run by the service itself. A job runs a command or a model prompt (optionally on the agent route in a project). Jobs live in config/schedule.json; set "enabled": true there to turn the scheduler on. Run now works either way.

These references never block model use. Usage is grouped per block: blocks of hours start at resetAt (local time) each day, and the last one is cut at the next reset.

Log in to services once and the orchestrator keeps the login, so you and the models can use them without pasting tokens again. Logins are encrypted with Windows (DPAPI, this user account only) in data/vault.json, never sent to the browser again, never shown to models, and never published. Use a fine-grained token limited to the repos you want to share; creating issues or comments still asks for confirmation. Add other token-based services under providers in config/connections.json.

How to get a GitHub token

GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate. Pick the ItMustBeThursday/HomeAI repo with Contents, Issues, Pull requests and Actions access, as needed. For one-click "Sign in with GitHub", register an OAuth app with Device Flow enabled and put its client ID in config/connections.json under github.clientId.

The service always requires a token. This PC's WebUI picks up the admin token automatically. Other devices get a limited token: read dashboards, chat read + models (never shell or agents), logan the Logan feed only, admin everything. Tokens are shown once and stored only as hashes.

Reaching the service from other devices

By default it listens on this PC only. Edit config/network.json and restart: set host to 0.0.0.0 (or your Tailscale IP), add names to allowedHosts or set allowPrivateIPs for LAN/Tailscale addresses. Shell, agents, config and device management only work from this PC unless remoteAdmin is true. Private HTTPS: tailscale serve --bg 18850, then add the Tailscale name to allowedHosts. See README, "Network access".
