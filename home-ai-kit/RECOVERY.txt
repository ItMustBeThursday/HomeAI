The repair targets the latest repository layout, without applying the old
connector/installer templates over your newer app/evolution work. It stops only

Open the newly created recovery chat using the printed link/session label.
Returning to an old native session can retain its pinned harness and transcript.
A selected runtime and a model are distinct: Codex cannot serve an Anthropic
model. Claude CLI/native bindings can also keep a Claude-owned transcript even
when the displayed fallback model label changes. API-key errors indicate an
incorrect route or unavailable auth mode, not a need to buy API credits.

Recovery keeps a single provider/runtime and no automatic fallback for main
chat. It preserves existing worker records and files but disables the two HomeAI
background plugins so broken queued work cannot immediately monopolize the GPU
or paid account. Do not rerun the old adaptive installer immediately: its
before_model_resolve hook changes provider/model without migrating a native
session's runtime/transcript. Cross-provider delegation belongs in independent
worker sessions; a native main chat should keep its own compatible runtime.
Local recovery also narrows the main tool catalogue; a brand-new local chat can
otherwise exceed context with system/bootstrap/tool schemas alone. A 200k hosted
conversation cannot be assumed to fit a local 8k/16k model after quota fallback.

App/evolution source, instructions, tool execution permissions, old conversations
and credentials remain intact. The config snapshot and backup path are recorded

reviving the failing process loop. Use the existing Restore-HomeAI.ps1 with the
verified snapshot for a full operator-chosen rollback; no rollback is automatic.
