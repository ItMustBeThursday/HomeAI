OFFLINE JAVASCRIPT EXECUTION

After the orchestrator installer has succeeded, run from the gaming-PC clone:
  cd D:\HomeAIGit\HomeAI
  git pull --ff-only
  cd home-ai-kit
  powershell -NoProfile -ExecutionPolicy Bypass -File .\Enable-HomeAIExecution.ps1

The installer stops owned services, verifies a backup, copies the existing
pinned Node runtime and installs one locally owned plugin. No new model/API key,
Linux distribution, Docker or administrator installation is required.
It enables the runner only after the actual target isolation probe passes.
Configuration rollback retains the prior chat routes and a valid disabled
execution plugin entry. It does not erase project files or repeat logins.

WHAT WORKS
homeai_check kind syntax: Node --check for a .js/.mjs/.cjs entry.
homeai_check kind test: dependency-free Node built-in node:test execution.
Explicit relative entry file only; no command strings, glob patterns or npm.
Use .mjs for app logic and tests, or include package.json with type module.
Outputs: real exit code, logs, actual test counts and copied-source hashes.
Zero real tests, skipped-only tests, failures and timeouts do not pass.
Test names should describe behavior; a single test named exactly like its file
is conservatively treated as a file-level result, not meaningful test evidence.

Example chat request:
Build a dependency-free habit tracker in project habits. Use a parallel plan:
Codex writes logic.mjs, index.html and app.js; Claude writes logic.test.mjs
using node:test; local Qwen writes acceptance-cases.md. Then assign Codex a
dependent integration job owning logic.mjs, index.html and app.js, with
requiredChecks [{"kind":"test","entry":"logic.test.mjs"}] and a 4-step
budget to run tests and repair its own files. Have Claude write REVIEW.md after
integration, summarizing actual test results and remaining browser checks.

PARALLEL OWNERSHIP HANDOFF
Concurrent assignments cannot own the same output path. A later assignment
can own an earlier output only when its dependencies include every earlier
owner. The runner never edits live project files; only the file broker does,
using fresh hashes and verified pre-change backups.

ISOLATION
Each check executes in a new Windows AppContainer profile with zero network
capabilities, plus Node's permission model. No network capability or loopback
exemption is granted. Node has read access only to the copied snapshot/runtime,
no filesystem write permission, no addons, child processes or workers.
Account environment variables are not inherited. Required Windows profile
variables point to the empty sandbox profile, not the user's normal profile.
A Windows job object caps execution to one process and 1 GiB, kills the process
when its supervising launcher exits, and enforces a 30-second run timeout.
The broker serializes checks and captures bounded output (1 MiB combined).
Snapshots refuse links, credentials/hidden directories, node_modules and binary
input; maximum 200 text files and 10 MiB per project snapshot.
Profiles and temporary ACL grants are removed on a normal exit. Abrupt process
termination can leave an inert profile/read-only grant; no uncertain run is
automatically replayed. Reports and snapshots remain available for inspection.

PERSISTENCE AND EVIDENCE
state\execution\runs\<id> contains request.json, input snapshot, stdout.txt,
stderr.txt, native-result.json and report.json. Job-bound requiredChecks must
have passed reports for that exact job and matching current source hashes.
Changing tested source invalidates its previous result for required-check
verification. Jobs still end ready-for-review rather than approved/deployed.
Generated tests need independent review; passing tests do not certify all app
behavior, security, accessibility or browser rendering.

NEXT BACKENDS
This runner does not install npm packages or run arbitrary build scripts,
PowerShell, Python, browser UI tests or native binaries. Those need additional
verified execution backends. Semantic memory, professional document rendering,
image generation and voice remain separate capabilities. Heretic stays staged
until target Python/PyTorch/HIP readiness is known.
