LEARNING
Each completed worker step records actual provider/model, wall-clock latency,
reported input/output/cache/total tokens and verified check evidence. Missing
usage is unknown, not zero. API prices do not stand in for subscription quota.
Repeated native fallback temporarily penalizes the unavailable requested model;
it is not a claimed precise remaining-token balance or reset prediction.
Preferences recompute as new evidence arrives. Five independent jobs and at
least three human ratings are required before quality ratings change a prior.
Five jobs with passing generated tests provide only a small positive signal.
Files merely existing provide no positive quality evidence. Faster responses
and token savings have bounded penalties so they cannot dominate quality.
Every tenth normal-priority role assignment may use another qualified candidate
instead of the favorite; this replaces a normal assignment, never duplicates it.
High-importance assignments do not explore. Queued new jobs refresh routing
when their first step is dispatched, so earlier phases can inform later phases.
Models are then held stable through the job's steps, except native provider
fallback; new jobs can choose differently.
This learns routing preferences and saved guidance, not new model weights.

CHAT AND WORKERS
With automatic coordinator routing on, planning/coding/design/review requests
select a hosted coordinator by role. Ordinary chat keeps the configured session
choice, and explicit cron/heartbeat routing is left to its own configuration.
Full chat history is not sent to tiny local workers. Small local work
uses bounded delegated prompts. Automatic routing can supersede a manual chat
model selection. Use /homeai_auto off to preserve manual session selection;
/homeai_auto on restores automatic routing. Both changes have restore IDs.
All Codex variants share one background provider lane, all Claude variants
another, and all local chat models the one GPU lane. Four admitted turns include
the coordinator. One local model is resident at a time; switching has load cost.
Several models on disk do not imply simultaneous GPU execution or zero overhead.

MANAGED AUTONOMY
The coordinator can use homeai_maintain to queue a checked catalogue model or
revise state/router/guidance.txt. Guidance edits require a fresh read hash, a
reason, a verified backup and a journalled revision. Only this managed guidance
slot is editable; arbitrary config, tool permissions and runtime scripts are not.
The model staging service downloads from fixed checked Ollama tags, verifies
source/alias pins, refuses replacement of a different existing alias, probes
chat-tool support/GPU residency and reports whether automatic routing was enabled.
Model quality still needs real checks and ratings; a readiness probe is not a
claim that the model equals a frontier model. Downloads are queued asynchronously
and processed when background jobs are idle. A new interactive local turn can
still overlap the probe; the single-model Ollama scheduler serializes inference.
At most two pending stages and 30 GiB planned new downloads per UTC day; 25 GiB
disk space is reserved. The catalogue can grow through a reviewed kit update;
the model cannot execute an arbitrary Internet installer or choose an unchecked
weight source. Restoring routing keeps downloaded weights on disk but unused.
Routine changes appear in the ledger and must be reported by the coordinator.
Use /homeai_changes for completion reports even when no chat inference runs.
Interrupted downloads/probes require inspection rather than silent replay.
